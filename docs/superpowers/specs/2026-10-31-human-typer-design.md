# Human Typer 设计

日期：2026-10-31

## 目标

一个用于演示和录屏的 macOS 浏览器插件：把给定文本以接近真人的节奏打到当前光标位置，并偶尔故意打错、退格、改正。画面上不出现调试提示条。

本项目不针对考试监考、作业或 AI 代写检测、打字过程回放、在线测评及平台反自动化风控做任何规避。

## 范围

**第一版包含**
- Chrome 和 Arc 插件（Manifest V3），搭配 macOS 本地程序
- 纯文本输入，支持中英文混合
- 可调速度、出错率、停顿强度
- 动作协议预留格式扩展能力（见“协议”一节）

**第一版不包含**
- Windows 和 Linux 支持
- 录制功能、定时任务、多段文本队列
- 带格式文本的实际输入（后续升级）

## 架构

```
插件弹窗 → 后台脚本（生成动作序列）→ Native Messaging → Swift 本地程序 → 系统按键
```

| 单元 | 职责 | 依赖 |
|---|---|---|
| `extension/planner.js` | 文本和参数 → 动作序列，纯函数，可传入随机种子 | 无 |
| `extension/popup.*` | 设置界面、发起任务、显示状态，参数存入 `chrome.storage.local` | 后台脚本 |
| `extension/background.js` | 调用 planner，持有 Native Messaging 连接，转发状态 | planner、本地程序 |
| `host/Core.swift` | 协议校验、分帧、动作执行和停止判断，可独立测试 | Foundation |
| `host/main.swift` | 发送系统按键，读取前台应用和用户操作，程序入口 | Core、CoreGraphics、AppKit |
| `install.sh` | 编译、本地签名、向 Chrome 和 Arc 注册本地程序 | swiftc、codesign |

插件的 `manifest.json` 写入固定的 `key`，使扩展 ID 不变，本地程序注册清单才能长期匹配。

## 使用流程

1. 在弹窗里粘贴文本、设置参数，点开始。
2. 倒计时 5 秒内点进目标输入框，弹窗自动关闭。
3. 本地程序在倒计时结束时记录前台应用，然后向当前光标位置打字。
4. 打字完成或停止后，再次打开弹窗可看到结果状态。

## 打字节奏

- 默认速度 60 WPM，按“每 5 个字符算一个词”换算基准间隔。
- 每次按键间隔服从对数正态分布，均值由速度决定。
- 标点和换行后停顿加长；按停顿强度偶尔插入约 1 秒的思考停顿。

## 出错与改正

默认出错率 3%，按可出错的输入单元计算。

- **英文**：打成 QWERTY 键盘上的相邻键，或把相邻两个字母打反。
- **中文**：按 2 到 4 个字一组上屏。错误来自内置的小型同音字表，如“在/再”；表中没有的字不出错。
- **改正**：打错后再多打 0 到 3 个字符才“发现”，停顿片刻，退格到出错位置，重新输入。
- **不变式**：在不受页面干扰的前提下，按序执行全部动作后的文本必须与原文完全一致。

## 协议

Native Messaging 使用 4 字节长度前缀加 JSON。

插件发给本地程序：

```json
{
  "v": 1,
  "cmd": "start",
  "startDelayMs": 5000,
  "actions": [
    { "type": "text", "value": "H" },
    { "type": "wait", "ms": 120 },
    { "type": "key", "key": "backspace", "modifiers": [] }
  ]
}
```

本地程序发给插件：

```json
{ "v": 1, "event": "done" }
{ "v": 1, "event": "stopped", "reason": "app_switched" }
{ "v": 1, "event": "error", "code": "no_accessibility_permission" }
```

`stopped` 的 `reason` 取值：`app_switched`、`user_input`、`user_cancel`。

第一版的 `key` 动作只接受 `backspace` 且不带修饰键，但字段结构是完整的。

### 格式升级的兼容规则

后续升级指：输入粗体、斜体、标题、列表、链接等带格式文本，第一版不实现。约定如下：

1. **输入与计划分层**：`planner.js` 的输入是段落和文本片段（runs），第一版的纯文本是“只有一个无样式片段”的特例。升级时新增的是解析器和样式动作，不重写节奏和出错逻辑。
2. **用快捷键实现样式**：格式通过 `key` 动作发送编辑器快捷键（如 `cmd+b`），不新增执行机制。不同编辑器的差异放在插件的适配表中，本地程序不感知。
3. **版本校验**：协议变化不兼容时递增 `v`。本地程序在开始打字前校验版本和全部动作类型，遇到不支持的内容就返回 `error`（`code` 为 `unsupported_protocol`），一个字也不打，避免只打出一半。
4. **出错范围**：出错和退格只发生在同一样式片段内，避免改正操作破坏样式状态。

## 安全与异常

系统按键会发给当前前台应用，因此出现以下情况时立即停止：

- 前台应用不再是开始打字时记录的应用
- 用户按键或点击鼠标：通过 `CGEventSourceSecondsSinceLastEventType` 读取 `hidSystemState`，只判断是否有真实操作，不记录内容，也不需要输入监控权限

其他异常：

- 缺少辅助功能权限：返回 `error`，弹窗给出授权说明。
- 本地程序未安装或连接断开：弹窗提示运行 `install.sh`；连接断开时本地程序同时停止打字。

## 已知限制

- 首次使用要授予“辅助功能”权限，重新编译后可能要再授权一次。
- 同一浏览器内切换标签页不会触发停止，字符会打到新标签页。
- 无法读取并校验输入框内的最终文本，页面的自动补全等干扰不会被发现。
- 目标页面的快捷键可能拦截部分字符。
- 换行以 Return 键发送，在聊天类输入框中可能直接发送消息。

## 验证标准

- **planner 单元测试**：多个随机种子下模拟执行动作序列，结果都与原文一致；实测速度接近设定值；出错率接近设定值。
- **host 测试**：验证消息收发、动作顺序、协议校验；用假的事件发送器验证两类停止条件。
- **真实环境**：在 Chrome 中对 `input`、`textarea`、`contenteditable`、Google Docs 用中英文混合文本各跑一遍，最终文本正确；切换应用或按键后立即停止。此项需要用户先完成辅助功能授权。
